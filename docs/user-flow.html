gemspot 유저 플로우 초안

전체 플로우

웹으로 배포하므로 시작점은 사용자가 이미 저장해 둔 이미지를 올리는 것이다.

  1. 이미지 업로드

    확정 담당 · 상욱
    화면 · 업로드
    • 업로드 버튼을 누르면 파일 선택창이 열리고, 앨범에 저장해 둔 스크린샷을 고른다
    • 웹 표준 파일 업로드로 처리한다 — 스크린샷 감지나 공유 시트 같은 OS 동작에 기대지 않는다
    • 여러 장 한 번에 올릴 수 있는지 미정

    앱이었다면 공유하기 · 백탭 링크 · 스크린샷 자동 감지로 바로 넘어오게 할 수 있었다. 셋 다 OS 동작이 필요해 웹에서는 쓰지 않는다.

  2. 이미지에서 주소 추출

    확정 담당 · 상욱

    OCR로 이미지 속 텍스트를 읽어 주소를 뽑고, 결과를 사용자에게 알린다.

    성공

    추출됐다고 알린다 — 알럿 또는 결과 페이지 방식 미정

    실패

    OCR이 주소를 못 읽은 경우. 실패했다고 간단히 알리고 다음 단계의 실패 목록으로 보낸다

  3. 추출 결과 목록

    확정
    화면 · 결과 목록 (탭 2개)

    탭 1 · 성공 목록

    주소가 잡힌 이미지들. 여기서 지도로 넘어간다

    탭 2 · 실패 목록

    OCR이 판별하지 못한 이미지들을 앨범처럼 모아 본다. 다시 시도하거나 주소를 직접 입력한다 직접 입력 지원 여부 미정

  4. 지도에 핀 찍기

    확정 담당 · 가은
    화면 · 지도
    • 지도는 이미 그려져 있는 상태에서 시작한다
    • 이미지에서 뽑은 텍스트를 주소 · 좌표로 맞춰, 그 위치에 핀을 찍는다
    • 핀을 찍은 위치로 지도를 이동시킨다
    • 내 위치를 함께 보여줄지 미정 — 기능으로 넣을지부터 정해야 한다

    네이버 Geocoding API에 OCR로 뽑은 주소 문자열을 query로 넘기면 addresses[]가 온다. 핀을 찍는 데 쓰는 값은 x(경도) · y(위도)이고 둘 다 문자열로 온다. 함께 오는 roadAddress · jibunAddress는 저장용, addressElements의 SIDO · SIGUGUN은 지역 필터용으로 쓸 수 있다. meta.totalCount가 0이면 결과가 없다는 뜻이므로 실패 목록으로 보낸다.

  5. 스팟 저장

    미정 · 담당 미정
    화면 · 저장 · 상세

    미팅에서 "누군가 해줘"로 남은 영역이다. 저장 시 붙일 정보로 언급된 것:

    • 카테고리 분류 — AI가 분류하고 목록 필터로 쓴다
    • 방문 여부 · 방문 횟수
    • 한줄평 · 메모

  6. 내 스팟 지도 — 저장된 핀 보기

    담당 미정
    화면 · 내 스팟 지도
    • 저장해 둔 스팟들을 지도 위 핀으로 한눈에 본다
    • 핀을 고르면 그 스팟의 상세로 간다 미정
    • 기본은 1인 사용 확정

  7. 필터 · 카테고리

    미정 · 담당 없음

    카테고리로 스팟을 걸러 보는 화면. 지도 보기와 분리했다. 지금은 맡은 사람이 없어 구현 시점이 정해지지 않았다.

  8. 스마트 동선 가이드

    확정 담당 · 화균, 주히(고민중)

    저장된 장소들을 모아 어디를 어떤 순서로 갈지 여정을 제안한다.

    • 제안의 입력 범위(전체 저장분 · 지역 · 기간) 미정

이후 확장 — 다 하고 나서

  1. MCP로 상용 AI 서비스 연결

    후순위

    외부 AI가 내가 스크랩한 장소 목록을 읽고, 키워드를 받아 장소를 제안한다. 미팅에서 "이건 나중에 합시다. 다 하고"로 정리됐다.

  2. 통계 · 리뷰 기반 추천

    후순위 담당 미정
    • 차트 — 예: 26년에 많이 가본 장소 TOP 10
    • 리뷰를 반영한 비슷한 결의 AI 추천
    • 광고 연결 아이디어 단계

  3. 다른 사람에게 공유

    후순위

    1인 사용이 기본이고, 시간이 남으면 공유 기능을 추가하기로 했다.

  4. 대화형 챗봇

    미정

    AI 활용 방향으로 언급만 됐고, 어느 화면에 어떻게 붙일지는 정해지지 않았다.

확정된 전제

  • GitHub Organization은 유료라 쓰지 않고 개인 배포로 간다
  • 기본은 1인 사용, 공유는 시간이 남으면 추가한다
  • 앞으로 모든 진행은 GitHub 이슈로 관리한다
