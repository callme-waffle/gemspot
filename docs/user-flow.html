gemspot 유저 플로우 초안

전체 플로우

웹으로 배포하므로 시작점은 사용자가 이미 저장해 둔 이미지를 올리는 것이다.

  1. 이미지 업로드

    확정 담당 · 상욱
    화면 · 업로드
    • 업로드 버튼을 누르면 파일 선택창이 열리고, 앨범에 저장해 둔 스크린샷을 고른다
    • 기본은 웹 표준 파일 업로드로 처리한다
    • 모바일 웹에서 공유하기로 스크린샷 화면을 바로 받을 수 있으면(Web Share Target) 그렇게 구현한다 확인 필요

    파일 업로드 — 4단계

    1. 인스타그램에서 스크린샷을 찍는다
    2. 홈 화면으로 나가 gemspot을 연다
    3. 업로드 버튼을 누른다
    4. 앨범에서 아까 그 사진을 찾아 고른다

    공유하기 — 2단계

    1. 인스타그램에서 공유하기를 누른다
    2. 공유 목록에서 gemspot을 고른다

    앱을 설치하지 않아도 되고, 앨범에서 사진을 다시 찾는 과정이 사라진다. 다만 홈 화면에 설치(PWA)해야 공유 목록에 뜨고 기기 · 브라우저를 탄다.

  2. 이미지에서 주소 추출

    확정 담당 · 상욱

    OCR로 이미지 속 텍스트를 읽는다. 읽어내는 것은 장소와 가게명이고, 그 결과를 STEP 3으로 넘긴다. 갈리는 기준은 화면에 도로명 주소가 찍혀 있는지 하나다. 여기서 말하는 성공 · 실패는 OCR이 읽어냈는가이지, 지도에 핀이 찍혔는가가 아니다.

    • 한 장에 가게가 여러 곳 담긴 게시물이 있다(피롤츠 · 파브리키친이 한 화면). 주소가 둘 이상 나오면 각각을 따로 뽑는 쪽으로 구현한다 확인 필요

    성공 — 주소가 찍혀 있다

    1. 피롤츠 커피하우스 · 서울 용산구 한강대로 56-1, 2층
    2. 파브리키친 · 서울 용산구 한강대로15길 23-6
    3. 익스프레스노원바이미라쥬 · 서울 노원구 화랑로 608

    Geocoding에 넣어 좌표가 나올 가능성이 높다. 실제 변환은 STEP 4에서 한다.

    실패 — 지역명과 가게명뿐이다

    1. 한강동 · 용산역 · 용산구
    2. 에그앤플라워 · 용산동2가

    번지가 없어 가게 위치를 특정할 수 없다. 동 이름만으로 핀을 찍으면 엉뚱한 곳에 꽂히므로 실패로 보내 직접 입력을 받는다.

  3. 추출 결과 목록

    확정
    화면 · 결과 목록

    STEP 2에서 넘어온 데이터를 받아 성공했는지 실패했는지 알럿으로 먼저 알린다. 그다음 성공한 건과 실패한 건을 보여준다.

    • 보여주는 형태는 페이지 · 모달 · 바텀시트 중 하나로 푼다 확인 필요
    • 성공과 실패를 가르는 방법도 탭 · 목록 분리 · 필터 중에서 정한다 확인 필요
    • OCR 결과는 바로 저장되지 않는다. 이 화면에서 사용자가 확정해야 스팟이 된다
    • 목록의 각 건마다 저장 · 삭제를 고를 수 있다
    • 여러 건을 한 번에 저장하거나 삭제할 수 있어야 하는지 확인 필요

    성공한 건

    주소가 잡힌 이미지들. 뽑힌 주소가 맞는지 사용자가 보고 저장할지 버릴지 고른다. 저장을 고른 건만 STEP 4로 넘어간다

    실패한 건

    OCR이 판별하지 못한 이미지들을 앨범처럼 모아 본다. 주소를 직접 입력하거나, 목록에서 삭제한다. 재시도는 두지 않는다 — 같은 사진을 다시 읽어봐야 결과가 달라지지 않는다. 직접 입력한 건도 성공한 건과 같이 STEP 4로 보낸다

  4. 확정한 스팟 저장

    확정
    • 화면이 아니다. 확정된 건을 서버로 보내는 내부 처리다
    • STEP 3에서 확정한 주소를 좌표로 바꾼다. OCR로 뽑은 주소든 직접 입력한 주소든 여기서 한 번에 검증한다 — 좌표가 나오지 않으면 저장하지 않는다
    • 상호명 · 주소 · 좌표를 서버로 보낸다
    • 별도 백엔드 없이 Next.js 하나로 처리한다
    • 어디에 저장할지 확인 필요
    • 카테고리 분류를 함께 저장할지 미정 — AI가 분류하고 목록 필터로 쓰는 값이다
    • 성공하면 STEP 5로 넘어간다. 실패하면 STEP 3에 머문 채 알럿이나 토스트로 오류를 띄워 무엇이 잘못됐는지 눈에 보이게 한다

    네이버 Geocoding API에 OCR로 뽑은 주소 문자열을 query로 넘기면 addresses[]가 온다. 핀을 찍는 데 쓰는 값은 x(경도) · y(위도)이고 둘 다 문자열로 온다. 함께 오는 roadAddress · jibunAddress는 저장용, addressElements의 SIDO · SIGUGUN은 지역 필터용으로 쓸 수 있다. meta.totalCount가 0이면 결과가 없다는 뜻이므로 저장하지 않고 오류를 띄운다.

  5. 지도에 핀 찍기

    확정 담당 · 가은
    화면 · 지도
    • 저장이 성공하면 이 화면으로 넘어와, 저장된 내용을 지도와 함께 다시 확인한다
    • 저장된 좌표에 핀을 찍고, 지도를 그쪽으로 이동시킨다
    • 화면 아래에는 저장된 정보를 함께 띄운다
    • 닫으면 초기 화면으로 돌아간다
    • 방금 찍은 핀만 보여준다. 저장된 핀 전체를 보는 곳은 STEP 6이다
    • 내 위치를 함께 보여줄지 미정 — 기능으로 넣을지부터 정해야 한다

  6. 내 스팟 지도 — 저장된 핀 보기

    담당 미정
    화면 · 내 스팟 지도
    • 저장해 둔 스팟들을 지도 위 핀으로 한눈에 본다
    • 핀을 고르면 그 스팟의 상세로 간다 미정
    • 기본은 1인 사용 확정

  7. 필터 · 카테고리

    미정 · 담당 없음

    카테고리로 스팟을 걸러 보는 화면. 지도 보기와 분리했다. 지금은 맡은 사람이 없어 구현 시점이 정해지지 않았다.

  8. 스마트 동선 가이드

    확정 담당 · 화균, 주히(고민중)

    저장된 장소들을 모아 어디를 어떤 순서로 갈지 여정을 만든다. 출발점부터 한 곳씩 쌓아 올린다.

    1. 출발점 고르기 내 위치 · 지도에서 직접 찍기 · 저장된 목록에서 고르기
    2. 1번 고르기 저장된 스팟 중에서 다음 목적지를 고른다
    3. 추가로 쌓기 더 들를 곳이 있으면 추가를 눌러 2번, 3번을 붙인다
    4. 경로 그리기 다 골랐으면 지도에 경로선과 번호를 그린다
    • 방문 순서는 사용자가 쌓은 순서 그대로다. 자동 정렬은 하지 않는다
    • 중간에 뺄 수 있어야 한다. 빼면 뒤 번호가 당겨진다
    • 구간마다 이동 시간과 거리를 보여준다
    • 거리는 직선거리 계산으로 낸다. 네이버 API로 실제 경로를 받을 수 있는지 확인 필요
    • 지도 위에 경로선을 그리고, 출발 → 1 → 2 순으로 번호를 붙인다
